# 常见即时通讯功能 → Nexconn 模式映射

当截图或原型包含超出基础消息时间线的现代即时通讯功能（自聊、贴纸、定时发送、回应、链接预览、文件夹、语音消息、匿名转发等）时加载本文件。

⚠️ 行表示本技能尚未记录官方文档。写实现代码前，应搜索 `references/llms.txt`，运行 `bash scripts/fetch-docs.sh <path>`，或将能力标为应用层并明确列出待办。

## 快速映射

| 功能 | 层级 | 实现模式 | 验证 |
| --- | --- | --- | --- |
| 自聊 / 已保存消息 / 云笔记 | SDK 之上的应用层 | 优先使用应用自有保存消息频道；使用单聊（自己给自己）前确认服务端允许 | 确认单聊(self,self)未被禁止 |
| 定时消息 / 稍后发送 | 应用服务端 + 待验证 | 客户端保存草稿和发送时间，服务端在时间点排队发送 | ⚠️ 搜索定时发送文档 |
| 在线后发送 | 应用服务端 + 在线状态 | 服务端等待收件人在线后发送，客户端只渲染排队状态 | ⚠️ 验证在线状态 API |
| 静默发送 | 应用层或推送配置 + 待验证 | 使用官方静默通知配置；否则在消息扩展中保存标记并关闭本地声音 | ⚠️ 验证推送配置 |
| 编辑消息 | SDK + 应用层策略 | 参见 `application-layer-rules.md` 的编辑窗口模式 | 已确认 |
| 撤回消息 | SDK + 应用层策略 | 参见 `application-layer-rules.md` 的撤回窗口模式 | 已确认 |
| 消息置顶 / 置顶栏 | 待验证 | 若有原生 API 则调用；否则由服务端保存状态并用自定义栏渲染 | ⚠️ 置顶 API 未收录 |
| 气泡表情回应 | 待验证 | 原生回应 API，或用 `{messageId, userId}` 后端状态和消息更新渲染 | ⚠️ 回应 API 未收录 |
| 静态/动画贴纸 | 应用层 + 自定义消息 | 载荷包含 `{stickerSetId, stickerId, mediaUrl, lottie?}`，通过自定义渲染器展示 | ⚠️ 验证自定义消息注册 API |
| 分类表情选择器 | 应用外壳 | 选择器是纯 UI，结果通过 SDK 发送 | 已确认 |
| 链接预览卡片 | 应用服务端 | 服务端获取 OG 元数据，附加到消息扩展或自定义卡片消息 | 本技能未记录 SDK 自动预览 |
| Web 语音消息录制 | Web Chat UI 不支持；Chat SDK 待验证 | Chat SDK 自定义 UI 需先验证音频/自定义媒体支持 | ⚠️ 验证 Web SDK |
| 语音播放波形/进度 | 应用外壳 | 应用根据服务端分析或下载的 Blob 渲染波形 | 应用负责波形 |
| 文件夹/标签分组 | 应用服务端 | 服务端保存用户文件夹配置，客户端在渲染层过滤频道列表 | 不要改变同步范围 |
| 文件夹邀请链接 | 应用服务端 + 自定义消息 | 服务端解析邀请 Token，客户端点击自定义消息后调用服务端加入 | 深链属于应用 |
| 匿名转发/隐藏发送者 | 应用层扩展 | 转发时移除展示卡片中的原发送者引用，审计记录保留在服务端 | 应用层 |
| 更换转发收件人 | 应用外壳 | 应用提供选择器，SDK 使用选中的频道发送 | 应用层 |
| 在线状态/最近上线 | 待验证 | 若有原生在线状态 API 则订阅，否则由服务端维护心跳 | ⚠️ API 未收录 |
| 机器人/系统发送者 | 应用服务端 | 服务端使用特权 Token 以指定用户 ID 发送，客户端按发送者 ID 渲染 | 无原生机器人抽象 |
| 带送达/已读勾选的频道列表 | SDK 内置 | 使用 SDK 消息状态事件 | 已确认 |
| 外呼卡片/通话按钮 | 跨技能（Nexconn Call） | 实时通话属于 Call SDK；历史卡片可由服务端记录后作为系统消息渲染 | 参见 SKILL.md 范围外说明 |
| 登录 UI | 应用层 | SDK 只接收服务端 Token，不虚构登录 UI | 参见 `credentials-and-token.md` |
| 营销页/第三方品牌元素 | 丢弃 | 不复制第三方品牌 | — |

## 使用方法

截图清点并丢弃非聊天内容后，将每项功能映射到上表，再合并到 `integration-workflow.md` 的差距表：SDK 内置对应 Built-in；可配置能力对应 Configurable；应用层 UI 对应 Application chrome；服务端能力保留 Application-server；跨技能/范围外内容放入最终待办的范围外部分；⚠️ 项目在验证前标为 Pending review。

## 消息扩展还是自定义消息类型

增加静默、隐藏发送者、定时来源等布尔标记，或给普通文本/图片/音频附加链接预览和回应状态时，使用消息扩展；需要新的气泡布局、互动卡片或新的消息种类时，使用自定义消息类型。两种方案都必须在所有客户端和服务端审计/搜索路径中保持一致；无法保证时，退回到按消息 ID 存储的服务端状态。

## 承诺能力前的验证

对所有 ⚠️ 项执行：

```
rg -n "<keyword>" references/llms.txt
bash scripts/fetch-docs.sh <matching-path>
```

索引没有对应关键词时，该能力尚未被本技能覆盖，应视为应用层并明确列出待办，不要编造 API 名称。
