# Nexconn Chat 集成工作流

当 SKILL.md 的分流流程将请求归类为**集成**时加载本文件。此时术语规范化和范围检查已经完成。

## 执行步骤

1. 项目识别：从项目文件推断平台/SDK，并阅读 `references/platform-setup/` 下对应平台文件。
2. 确认门禁：确认无法推断的输入。
3. 文档与代码验证：获取官方文档，再用已安装代码确认细节。
4. 决策框架：按五层决策流程选择并记录层级。
5. 实现：按以下规则生成代码。
6. 测试与验证：提供验证步骤。
7. 最终待办：输出已实现/未实现总结。

## 项目识别

在向用户提问前，先检查本地项目：

| 平台 | 检查文件 |
| --- | --- |
| Android | `build.gradle`、`settings.gradle`、Gradle 模块文件 |
| iOS | `Podfile`、`*.xcodeproj`、`Package.swift` |
| Web | `package.json`、`tsconfig.json`、框架配置文件 |
| Flutter | `pubspec.yaml` |

用 `rg` 搜索初始化封装、已安装包和版本、IMKit 定制点、Token 获取逻辑、本地化和 UI 文案规范。识别平台后先阅读对应平台导航文件，再确认 SDK/频道选择。

## 确认门禁

写集成代码前必须确定**平台、频道类型、业务场景**。SDK 选择只有在用户明确指定时才是输入约束，否则由五层决策框架决定。优先从项目和用户描述推断；无法推断时只问一个简短问题。多频道需求要说明每种频道的职责。现有 Nexconn 初始化、连接或频道使用视为已确认，只询问新增或变更值。

凭据门禁：可运行初始化需要 App Key 和 Token；绝不能在客户端放 App Secret、签名逻辑或特权 Token 生成代码；缺 App Key 时索取或提供明确的不可运行脚手架；缺 Token 时接入服务端变量或标记占位符。

## 文档与代码验证

**文档优先**：先从 `references/llms.txt` 搜索相关路径，运行 `bash scripts/fetch-docs.sh <path>`，完整阅读 `references/cache/` 中的官方指南，然后才检查已安装 SDK 的类型、源码和包内部。不要只凭类型定义逆向推断流程。

网络不可用且没有缓存时，可使用已安装代码和本地项目，但将不确定的 API、初始化顺序或集成方式标为“待文档复核”。文档与代码冲突时，按已安装版本实现并简要说明冲突；没有来源确认的细节不得编造。

## SDK 集成决策框架

实现前阅读 [SDK 集成决策框架](./sdk-integration-decision-framework.md)，按以下顺序评估：

1. IMKit 原生能力。
2. IMKit 定制扩展。
3. IMLib API 层。
4. 源码修改（需用户明确批准）。
5. 最终决策：实现、替代方案或报告不支持。

## 实现规则

遵循项目已有代码风格、目录结构、状态管理和 UI 约定。IMLib 自定义 UI 要按已验证 API 连接初始化、频道创建/打开、消息收发、监听器和清理，并在应用层处理 SDK 未强制的策略。IMKit 优先使用文档化的 hook、主题、自定义视图和组件覆盖；过滤和自定义渲染不得改变底层同步范围；默认语言为 `en_US`。

### 截图驱动实现（IMKit）

收到 2 张或更多截图时，先执行 `image-analysis-guide.md` 的清点、丢弃品牌/营销、拆分认证/通话、去重流程，并用 `feature-pattern-map.md` 给现代即时通讯功能分层。然后建立一张完整差距表：

| 功能 | 分类 | 说明 |
| --- | --- | --- |
| 频道列表、消息气泡、输入区 | Built-in | IMKit 无需配置即可渲染 |
| 消息菜单、输入工具栏 | Configurable | 通过 hook、菜单、开关、主题或扩展点 |
| 气泡背景色 | Configurable | 样式 token/主题/气泡配置 |
| Web 气泡全部左对齐 | Constrained | Web Component 可能锁定布局，完全控制需 IMLib |
| 搜索栏、标签过滤、在线状态 | Application chrome | 在外围由应用实现 |
| 定时发送、链接预览、已保存消息 | Application-server | 需要应用后端状态或任务，不能编造客户端 API |
| 回应、消息置顶、在线状态 | Pending review | 获取文档或在实现前标记待办 |
| Web 语音消息 | Unsupported | 能力矩阵明确标记不支持 |

在写代码前将差距表交给用户确认；对 Constrained 和 Unsupported 项明确说明接受限制、改用 IMLib 或放弃需求的取舍。确认后挂载 provider、应用配置并构建外围应用组件；不支持项必须明确告知并跳过，不得静默省略或编造变通方案。

## 测试与验证

在适用时构建或类型检查项目，验证初始化日志、Token 注入、连接及重连、目标频道、离线消息、推送、未读数、已读回执、提及、自定义消息和审核行为。Web UI 需检查桌面和移动端。提醒将调试日志切换为 WARN/ERROR 后再发布。常见问题包括 App Key 无效、Token 过期、频道类型错误、监听器未清理和目标平台不支持。

## 最终待办处理

输出两份清单：

- **已实现功能**：按 Built-in、Configurable、Application chrome、Application-server 分组。
- **未实现功能**：

| 功能 | 状态 | 原因 |
| --- | --- | --- |
| 功能名称 | 未实现 / 不支持 / 范围外 / 待复核 | 简要说明 |

只使用上述状态值。若截图包含通话、会议、直播、登录/注册/2FA、第三方品牌元素或仅服务端功能，必须增加**范围外项目**部分，并说明对应归属或缺失条件。

## TODO 清单

列出仍需用户提供或后续完成的项目，例如 App Key、Token 端点、服务端队列、待验证 API、用户确认的源码修改或不支持的需求。

## 常见问题处理

若网络不可用，使用缓存或已安装代码并标记待复核；若官方文档和安装版本不一致，以安装版本为实现依据并报告冲突；若项目平台无法识别，只询问一个平台问题；若用户指定的 IMKit 无法满足需求，说明限制并在切换到 IMLib 前获得同意。
